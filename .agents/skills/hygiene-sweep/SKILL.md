# hygiene-sweep：只加不减的地方，定期减一次

代理写代码和测试的成本接近零，所以仓库会只增不减。巡检的产出是几个小的、各自独立的清理提交，或者一份留给人决定的清单；不在巡检里做大改。

先定范围：`git log --since="30 days ago" --name-only --pretty=format: | cut -d/ -f1-3 | sort | uniq -c | sort -rn | head`，看改动最密的五处。

1. **浅的抽象和坏样本。** 在热点里找：只有一个实现的接口、只转发的包装、和实现一样复杂的“辅助”类型、同一条规则的第二份实现。问：删掉它，复杂度是集中了还是只是搬家？后来的改动会模仿这里的写法，粗糙的地方先修。
2. **声明了但没有强制或没人读的东西。** 配置键、属性、错误码、指标：`grep` 它的读取方。没有就删掉声明，它只会让人以为有这个功能。
3. **测试。** `scripts/check.sh` 末尾列出最慢的测试：超过一秒的，看它是在等什么（等超时、等一个之后才打开的门、输入大得没有必要）。同一个行为的重复用例合并进已有的 `[Theory]`；删掉以后没有任何性质失去保护的测试删掉。`python3 scripts/gate.py` 里 `Thread.Sleep`、`Task.Delay` 的存量只许减少，减少后把脚本里的基数调低。
4. **决定。** 对改动过的领域读一遍 `docs/decisions/<领域>.md`：哪些条目说的已经不是现在的做法（改写或删掉），哪些只是在复述代码（删掉），哪些前提变了（规模、依赖、用户的要求）该重新考虑。门禁只能查出名字不存在了，查不出理由过时。
5. **使用者文档和示例。** 近期的公开 API、配置键、错误信息变化，`docs/guide/`、`README.md`、两个示例和它们的 Schema 跟上了吗？按 `docs/guide/` 从头做一遍，卡住的地方就是要修的地方。
6. **术语。** 新增的公开类型、配置键、文档有没有引入 `docs/glossary.md` 之外的同义词；有新概念时补进术语表。
7. **跨项目的改名或签名变化。** 调用点很多时分三步，每一步都保持全绿：先加新的并让旧的转发；再按依赖方向自下而上分批迁移调用方；最后删掉旧的。1.0 之前不保留过渡层，三步在同一轮里做完。

每个清理提交说明删了什么、为什么可以删。拿不准的列出来问，不替人决定范围。
