# 内置算子与模型调用

- **`ModelScorer@1` 在加载时检查每个可能用到的模型版本**。每个版本：签名里的每个输入都必须在 `inputs` 里有映射，每个映射的输入都必须正好声明打分算子为它构造的张量（见下一条），每个映射的输出都必须正好声明它写入的列的类型和形状（`[-1]`，`list<E,N>` 列是 `[-1, N]`，批维度动态）；否则加载失败，错误指向 `/inputs/<名字>`、`/outputs/<名字>`，缺少输入时指向 `/model`，提示说明打分算子支持什么。原来只核对名字，类型或形状不符、少给输入的版本也能加载，然后每个请求都失败或走后备。签名里有、`inputs` 没给的输入是错误，因为模型签名没有“可选输入”的约定。规则只在 `ModelTensorRule` 一处，三个模型算子共用（见“成对和列表级重排”）。
- **模型张量的元素类型就是声明的类型，框架不做转换**（2026-11-21 用户要求；1.0 之前的不兼容改动）。映射的列或上下文值是什么类型、什么宽度，送给模型的张量就是什么：bool、int32、int64、float32、float64、string 各送同类型的 `[rows]`，定长列表 `list<E,N>` 送 `E` 类型的 `[rows, N]`，按行连续；上下文值广播到每一行。输出也一样：映射输出的张量是它写入的列的类型，`[rows]` 或 `[rows, N]`。原来内置算子有自己的映射：float32、float64 送 float32，bool（0/1）、int32、int64 送 int64，字符串不能送，输出只能是 float32。用户提出的场景：特征存储返回 int32 的特征，模型服务要 int32，特征日志也记 int32；框架把它送成 int64，使用者自己的模型客户端就要转回 int32；float64 特征被舍入成 float32，训练和服务看到的值不一样。框架面对的是使用者自己的模型和日志系统，不只是内置客户端，所以每个扩展点都交付声明的类型（`development.md` 第 6 节）。bool 不再变成 0/1：它和整数是不同的类型，模型要整数时映射一个 is_x ? 1 : 0 的衍生特征；使用者自己写的算子要转换，由它们自己决定。
  - 张量仍由配置决定，不看模型签名。回放按行输入的摘要匹配模型输出，摘要包含元素类型和形状；回放引擎和 `validate` 编译计划时不加载模型客户端，不能依赖签名；签名决定张量时，同一份配置有没有取到签名会构造出不同的张量，回放会把每行的输入都报成变了。签名声明的张量和构造的不一样是 `MODEL_TENSOR_MISMATCH`，hint 给出两种改法：改签名，或者映射一个签名要的类型的衍生特征。可空的值和变长列表在编译时就是 `MODEL_INPUT_TYPE`（变长列表的 hint 是声明长度），不需要客户端，`stratarec validate` 也能报。
  - 取值从列的存储按存活行直接复制进从请求租借的缓冲，分批是它的切片，不经过 float64 的中间列；int64 超过 2^53 的值也精确。上下文值在表达式里按提升的类型保存（int64、float64），广播时收窄回声明的类型；提升是精确的，所以收窄得到原值。上下文特征的符号带的是提升后的类型（表达式按它计算），计划的 schema 因此为每个上下文字段另记声明的类型（`ContextField.DeclaredType`，请求输入和上下文特征都有），模型输入按它构造张量。原来上下文特征只记了提升后的类型，宿主示例里声明为 float32 的 `ctx.user.affinity` 就被当成 float64。
  - 字符串张量每行一个字符串。客户端没有写的元素是 `null`，`ModelScorer@1` 写回之前让节点失败，不当成空字符串：空字符串是合法的值，`null` 是客户端的缺陷。回放包如实记下 `null`，回放时同样失败。
  - `ModelScorer@1` 的输出：客户端写出的类型和签名不一致时（签名说 float32，写的是 float64），节点失败，错误说明写出的类型、列和签名声明的类型（排序器怎么读分数见“成对和列表级重排”）。不按列的类型转换：那等于在边界上悄悄转换，客户端的缺陷会变成精度问题。
  - 输出的元素数必须正好是形状的元素数（行数，或行数 × 列表长度），多了也是失败。原来只拒绝少的：客户端按宽度 3 写了宽度 2 的列表列，按列宽切片后每行取到了下一行的值，节点照样成功；录制留下整个缓冲，回放按“元素数 / 批大小”推出另一个宽度，在线和回放切出不同的行。
  - 宿主用 `RequestInputs` 直接传入的 `list<string>` 可以含 `null` 元素（JSON 不能），转换时拒绝，错误指出是哪个元素：列表的元素都是值，模型和录制的摘要都不该收到 `null`。
  - 代价：签名把整数或 bool 声明为 int64 或 float32、把 float64 声明为 float32 的模型，加载时报 `MODEL_TENSOR_MISMATCH`，要改签名或映射衍生特征。回放包的格式随之升级（输出带上了类型，见“回放”），旧的包要重新录制。
  - `linear@1` 是浮点模型的替身，签名只声明 float32 `[-1]`，收到其他张量的调用失败；`random@1` 可以按真实模型的签名声明任何类型（见“`random@1` 是绑定层的替身”）。
- **字符串张量和文本是两种输入**。`TensorElementType` 有 `String`（每行一个字符串，按行切分）和 `Text`（整次调用的一个值：提示词、生成的回答）。考虑过合并，把文本当作形状 `[1]` 的字符串张量；没有合并，因为两者在回放里的匹配方式不同：张量按行切分进每行的摘要，文本整体计入摘要、只按整次调用回答。合并之后，单行调用的提示词首维是 1，正好等于 `batch_size`，会被当成逐行的输入。两者在 `NamedInput` 上各有工厂方法；对张量取 `Text` 会抛出异常，对文本取张量的值也一样。
- **IModelOutputWriter 按类型给缓冲：`GetValues<T>(name, count)`，T 是 bool、int、long、float、double 或 string**；文本用 `SetText`。原来只有 GetFloat32。一个泛型方法覆盖所有元素类型，客户端写的就是它的类型；读的一方（`TensorValues`）按记下的元素类型取值，类型不对时抛出说明两种类型的异常。`TensorValues` 是 `ReadOnlyMemory<T>` 之上的类型化视图，来源可以是数组，也可以是从请求租借的缓冲，不复制。
- **成对和列表级重排：`PairwiseRanker@1`、`ListwiseReranker@1` 重排前 `window` 行，与 `ModelScorer@1` 共用一套编译和取值**。三个算子的绑定、版本、输入编译、逐版本签名检查和取值是同一份代码（`ModelCallCompiler`、`ModelInput`），张量规则只在 `ModelTensorRule`：每行贡献的值由列类型决定（上一条），前导维由算子的布局决定，逐行 `[rows]`，成对 `[pairs, 2]`（排名高的一行在前），列表 `[1, rows]`；上下文值对每个批次元素广播，分别是 `[rows]`、`[pairs]`、`[1]`。签名的维度规则对三个算子相同：动态维（行数、对数、列表长度）必须声明 `-1`，因为写成固定值的批次维遇到别的大小会在运行时失败；固定维（成对的 2、列表批次的 1、向量的 N）声明成那个值或 `-1`，签名用 `-1` 表示任意。这对 `ModelScorer@1` 是放宽，向量的 N 现在也可以声明 `-1`。
  - 分数是 float32 或 float64，签名声明哪种都行：分数只用来排序，两种宽度都没有理由拒绝，模型服务常常返回 float64。其他类型（整数、bool、字符串）在加载时是 `MODEL_TENSOR_UNSUPPORTED`，客户端写出其他类型时节点失败，按 `on_failure` 处理。运行时按客户端写出的宽度读，不再和这个版本的签名核对：核对要在计划里按版本记下签名声明的宽度，而两种宽度排序都正确；回放不加载客户端，没有签名可核对，只有录下的类型。“什么是分数”只在 `ModelTensorRule.IsScore` 一处，加载检查、运行时读取和错误信息都用它。
  - 成对：窗口里每一对都比较一次。行的分数是期望胜场 Σp，对 (i, j) 给 i 加 p、给 j 加 1 − p；不数 p > 0.5 的场次，因为那样丢掉模型的把握程度，还要逐对规定平分。平分按 `entity_id`，不按进入时的顺序。偏好是 NaN 或不在 [0, 1] 时节点失败，不截断：输出 logit 的模型截断之后按噪声排序，看不出错；失败则走 `on_failure`，配 `skip` 时保持原顺序。
  - `max_pairs`（默认 1225，即窗口 50）是加载期上限：`window · (window − 1) / 2` 超过它是配置错误，请求期不截断。设计原来写超过时只比较排名靠前的对：那样靠后的行比较次数少，期望胜场不可比；窗口是静态配置，对数在加载时就确定。`max_pairs` 本身最多 2^29：每个输入把每对的两行取进一个数组，再大就放不下，原来要到请求期才因溢出失败。代价：窗口不能随请求变化。
  - 列表级：一次调用，没有 `batch_size` 也没有上限：列表是模型的输入单位，拆开会改变模型看到的内容，`window` 已经限制了一次调用的大小。按分数重排的规则与按列排序相同：高的在前，NaN 在后，平分按 `entity_id`。
  - 回放：两种调用都不带逐行的键，按整次调用的输入摘要录制和匹配，因为输出属于一对或整个列表，不属于某一行。代价：映射输入的张量（类型、形状或值）变了，受影响的调用在回放里就是 `not_recorded`，节点按 `on_failure` 处理；不能像 `ModelScorer@1` 那样按实体合成。窗口里换了行或换了顺序，只在改变了这些张量时才算变：两行的映射值相同时，交换它们得到同一个摘要，复用录下的输出也是对的，因为模型看到的就是同样的输入；要按候选身份匹配，把 `entity_id` 映射为模型输入。
  - 效果都声明为 `RowOrder | ColumnWriter`，`score_col` 可选。效果按算子静态声明，不随配置变；不写 `score_col` 时多出的 `ColumnWriter` 不影响任何判断：拉取屏障只看 `RowSource`、`RowFilter`，同一 `order` 的依赖检查有 `RowOrder` 就成立，足迹和非空产出检查看编译时记录的输出列。`score_col` 必须是可空的浮点列，因为窗口外的行没有分数；没有声明时是 `float32?`。
  - 比较的对数是每次调用的行（`BatchSize`），由 `stratarec.io.keys` 按调用计（标签是模型调用的 `stratarec.io.role = model`、`stratarec.io.target`）：调用后来失败或超时也算，它计的是成本；缓存答了的调用没有发出，不算；回放不计。原来的 `stratarec.model.pairs` 在节点发出调用时按次运行计一次，缓存答了的对也算进去，2026-11-22 的可观测性审计去掉了它（见“可观测性”）。
  - 评审建议的两项加固一起做了：取列时每个输入核对一次缓冲的实际类型与声明类型完全一致（同一类的不一致原来会被接受）；`linear@1`、`random@1` 要求输入的首维等于 `BatchSize`。
- **生成类算子在可选包 `StrataRec.Llm`，提示词用 Mustache，第一个算子是 `LlmReranker@1`**。框架不运行模型：大模型由用户实现的 `IServiceClient` 接入（文本进、文本出），框架负责模板、调用、解析回答和回放。包与 `StrataRec.Redis` 一样放在 `src/`，核心包不引用它，CLI 引用并注册。扩展包里的模型算子要用到的绑定、版本与签名检查、带种子的调用，从 `StrataRec.Pipeline` 公开成 `BoundModel` 等少数类型，不用 `InternalsVisibleTo`：第三方写模型算子需要同样的东西。
  - Mustache：模板没有逻辑，需要计算的值做成衍生特征，训练和服务共用一份定义，提示词里不出现第二种表达式语言。不做 HTML 转义，提示词不是 HTML，`{{x}}` 与 `{{{x}}}` 相同，这是有意与 mustache(5) 不同。不支持 partial 和改分隔符（加载错误）：每个模型输入一个模板，改分隔符会让错误的偏移难以对应。名字在加载时按节点的作用域解析（`ctx.*`、`param.*`，`rows` 区段里的 `col.*` 和 `rank`），记为节点的读取，所以特征先拉好；未知名字给出近似名。缺失值显式：可空引用必须在同名区段里使用，否则加载错误；`{{^rows}}`（窗口非空才调用，永远不渲染）和对必有值的标量开区段（总会渲染）也是加载错误。float32 按 float32 的最短往返形式渲染，`0.1` 显示为 `0.1`。区段最多嵌套 32 层：绑定和渲染每层递归一次，原来 60 万字符的深层模板在加载时就让栈溢出、进程退出。渲染写进每个线程保留的一个 builder，所以线程渲染过之后，每次请求只分配交给模型的提示词字符串；超过 256 Ki 字符的 builder 不保留，这么长的提示词每次还要分配 builder，因为让每个线程一直占着这么大的内存更不划算。Mustache 的解析器和语法树是包内部的类型，公开的只有 `PromptTemplate`：通用模板引擎不是这个包要长期兼容的接口。
  - 回答：必须是严格的 JSON 数组，只剥最外层的一层代码围栏，里面的反引号是内容（例如 JSON 字符串里的 ```）；不从文字里抠数组，因为那会掩盖提示词的问题，行为也随模型变化。部分有效的回答很常见，所以不在窗口里的元素（包括不是合法 Unicode 的字符串，无论是 JSON 转义的还是客户端字符串里原样的孤立代理字符：后者在编码成 UTF-8 之前改写成转义，否则编码器把它换成 U+FFFD，可能正好是另一个实体的 ID，评审；它若紧跟在奇数个反斜线后面，本身就是一个非法转义的字符，改写成转义会和前面的反斜线拼成合法的 `\\uD800`，所以这时写成 U+FFFD，回答仍是非法 JSON）和重复元素忽略并计数（`stratarec.model.answer_ids`，`outcome = used | unknown | repeated`）；一个有效元素都没有，或者不是数组，节点失败并引用回答开头，不改顺序，交给 `on_failure`；回答被截断时消息里说明，并提示调大 `max_output_tokens` 或缩小窗口。`answer` 没有默认值，由提示词决定：`rank` 省 token，`entity_id` 不会因为模型看错位置排错行。没列出的窗口行默认跟在后面（`keep`），也可以丢弃（`drop`）；效果静态声明为 `RowOrder | RowFilter`。
  - `max_output_tokens` 由客户端执行，因为只有客户端有分词器：客户端在 `ServiceStatus` 里回报生成的 token 数和是否在上限截断，引擎在调用结束的同一处计数（第 2 步起对所有服务调用：`stratarec.io.output_tokens`、`stratarec.io.truncated`），回放不计。设计原来写由算子停止读取，算子拿到的是完整的回答，无从停止。
  - 回放：调用按整次调用的摘要录制（提示词和 `max_output_tokens`；设了上限才进摘要，所以原有录制不变），种子是请求的种子，回放包里已有，不进摘要。录制保存回答原文、token 数和截断标记，回放返回同样的状态和消息；提示词只存摘要，不存原文，控制回放包的大小。代价：模板或提示词里的特征一变，调用就是 `not_recorded`，节点按 `on_failure` 处理；要看提示词原文，目前只能本地重新渲染。
  - 文本签名只检查元素类型是 text，不检查形状：各种推理服务对文本张量的形状约定不同（`[]` 或 `[1]`），而算子每个输入总是一个字符串。
  - 本地替身 `fixed_text@1`（`StrataRec.Models`）：设置声明文本输入和每个输出的固定回答，每次调用都回答它们，用于本地开发、测试和示例。
  - 第二期：`LlmAnnotator@1`（逐行标注）和 `GenerativeRetriever@1`（生成候选）。三个算子共用一个 `PromptTemplate`，按作用域区分：窗口（`rows` 区段，重排）、逐行（顶层的 `col.*`，标注）、整请求（只有 `ctx.*`、`param.*`，生成召回）；用了别的作用域才有的名字是加载错误，从别的算子拷来的模板在加载时就失败，而不是到模型的回答里才看出来。严格的数组遍历、围栏和引用回答只在 `LlmAnswer` 一处，元素怎么解释由各算子决定。SlateGenerator@1 不做：整页生成就是生成召回接大模型重排，没有单独算子的必要。
  - 标注每行一次调用（批大小 1，录制按实体做键）：一行的提示词只依赖这一行和请求，回答可以按实体复用，窗口变了也能逐实体回放；多行一次调用的回答绑在整个窗口上，窗口一变整次调用就是 `not_recorded`。代价：调用数等于窗口大小（默认 20，并发），每行分配提示词和调用对象，这是按外部调用分配，不是按候选。回答按列类型解析：文本去掉首尾空白和最外层围栏，空回答不可用；类别精确比较、区分大小写；bool 不区分大小写；数字用 JSON 数字语法，有限且在列的范围内。不可用的行就是缺失，不猜，不填默认值。有行缺失时节点是 `degraded`，原因里写计数、第一个失败和第一个不可用的回答；所有调用都失败才是 `Failed`，交给 `on_failure`；一行的客户端抛异常只算这一行失败，预算用完或调用方取消仍让节点失败。指标 `stratarec.model.answers`（`outcome = used | unusable | failed`）。没有声明的列是 `string?`。
  - 生成召回：一次调用，回答是实体 ID 的数组，最多用 `max_items` 个，它就是节点的行上限，决定候选表的容量。类型不对、重复、表里已有（`present`）、超过上限（`over_limit`）的元素跳过并计数；已有的行原地不动，因为行来源只追加、只写自己追加的行，失败时也只回收这些行，去标记别的来源的行就成了不能回滚的 `ColumnWriter`。超过上限之后的元素不再解释，但整个回答仍须是合法 JSON：截断的回答即使前面已有足够的 ID 也失败，与重排的严格规则一致。空数组是合法回答。生成的行和其他追加的行一样由拉取规划补齐特征；`rank_col` 是元素在回答中的位置，跳过的元素也占位置，与 `recall.best_rank` 一致。接在召回之后时，召回的归因列（`recall.*`）要声明为可空：生成的行没有这些值，按“缺失显式”不能写 0，加载时由 `ROW_SOURCE_AFTER_COLUMN` 指出。
  - 回放：单行调用的文本从“单独调用这个实体、输入相同”的成功录制合成，生成的 token 数和截断标记一并带回；多行调用的文本属于整次调用，不能拆分。合成不出来时，只用别的输入回答过的实体报 `inputs_changed`，其余报 `not_recorded`。按键取录制时还要求每行的输入摘要相同，失败的录制也一样：原来只比实体，同一模型、同一实体、另一个提示词（另一个节点）的失败会回答这次调用，挡住录制里它自己输入的成功回答。输入变了的调用即使录制里失败过，也按实体合成并报缺口，不重放那次关于别的输入的失败。
- **`GroupAggregate@1` 是分组统计的入门算子**（“范围调整”里组由成员决定的那种分组）。按一列分组（int64、int32、string）或者整张表一组，算 `count`、`sum`、`mean`、`min`、`max`、`std`（总体标准差）或 `rank`，写回组内每一行。用组合代替选项：每个作者最多两条是 `rank` 加 `ExpressionFilter`，请求内的分数标准化是不分组的 `mean`、`std` 加 `ExpressionScorer`，商家的组得分是按商家的 `max`；示例 `home_feed` 用前一种。`rank` 的顺序和 `TopK@1` 相同（缺失排最后、平分按 `entity_id`，同一个 `RowRanking`），所以组内名次留下的正是对这组做 TopK 会留下的行。缺失是显式的：分组键缺失的行不属于任何组，输出缺失；值缺失的行不参与统计，一组没有值时输出缺失；可能缺失的输出必须是可空列，声明成不可空时编译报错并提示。没有声明的输出列由节点隐式声明（`count`、`rank` 是 int64，其余 float64），声明了的可以是同类的另一种宽度（int32、float32）。输出是一个以列名为键的对象，实验可以单独增、改、删一项。值按 float64 读（同 `MmrDiversifier@1`）。分组用请求内存：字符串经临时键索引按内容编号，整数排序后编号，不按行分配。top_k_mean、`logsumexp` 有实际需求时再加。分组列或值列有错时，输出不能声明的列标为不可用，读它的节点不再连带报错（同评审的召回列）。`mean` 按行序递推：相同的值均值就是这个值、标准差恰好是 0；原来均值由和除以个数得到，差一个 ulp，标准化出 ±1。每步加 x/k − mean/k，求和与异号大值相减都不溢出。`std` 的第二遍以递推均值为中心（限制在组内最大 |x| 以内），按 LAPACK dlassq 缩放：离差除以组内最大离差后再平方，同时累计带符号的离差和，方差取 scale²·(平方和/n − (离差和/n)²)，小于 0 取 0。这是修正两遍法，对任意中心都精确：只用平方和时，递推均值在数值尺度上的舍入会进入结果，1e16+6、1e16+4 交替得 √2 而不是 1，[0, ε] 得 ε 而不是 0。组内最大 |x| 超过 float64 上限的一半时值先减半，离差不会溢出；结果先以组内最大 |x| 为上界（总体标准差不超过它）再还原尺度，所以任何有限输入都得到有限的标准差（四个 −MaxValue 加四个 +MaxValue 原来在还原尺度时变成无穷，非空输出使节点失败）。全是次正规数的组可能差一个次正规数的步长：不处理，修它要先放大尺度、多一遍扫描，而特征值落在 1e-308 附近的组实际不会出现。
- **没有声明的输出列在每个臂组合里只有一种类型**。隐式输出由第一个编译到的变体声明类型，所有组合共用这一份 schema；另一个变体写成别的类型（实验把 `count` 改成 `mean`，或者加一个可能缺失的分组键让输出可空）时，原来按第一个类型编译：均值被写成整数，缺失的计数让请求失败，而校验全部通过。现在 `TryWriteColumn` 对已经隐式声明的列要求类型完全相同，否则报 `COLUMN_TYPE_MISMATCH`，位置是后编译的那个变体（实验的改动在臂的补丁里）。只差可空性时提示在 `columns` 里声明成可空类型，两个变体都能写；种类不同时提示写到另一列。没有选“自动取更宽的类型”：读这列的表达式和下游算子是按某个类型编译的，静默变宽会改变它们在其他组合里的行为。
- **`SlidingWindowQuota@1` 按组排队**。每一步放“所在组在最近 `window − 1` 个名次里不到配额的最早一行”，语义不变；原来每一步从头扫描未放的行、再逐个数窗口，O(n²·window)，5,000 行两组各半连续排列时 9 ms。现在每组的待放行按原顺序排成队列，配额未满的组按队首的位置放进堆，放一行就把滑出窗口的那一行减掉，可能让它的组重新入堆；O(n log G)。等价性用随机分布（连续段、打乱、无组的行）与原算法逐一比对。分组键编号与 `GroupAggregate@1` 共用 `RowGroups`。
- **`MmrDiversifier@1` 按公式取相似度，λ 在 [0, 1] 内由编译保证**。每一步取 λ·分数 − (1−λ)·(与已选行的最大相似度) 最大的行，第一步只看分数；相似度是余弦，可以为负，任一方没有 embedding（或是零向量）时为 0。`embedding_col` 必须是定长浮点列表；相似度和表达式的 `cosine` 用同一个公式，逐位相同：`list<float32,N>` 按 float32 算点积和范数，`list<float64,N>` 按 float64，余弦在 float64 中由三者算出。原来“最大相似度”从 0 开始取最大，等于把相似度截到非负：和所有已选行方向相反的行被当成无关的行，排序与公式不符。第一步取分数最高的行（λ = 0 时公式里的分数项都是 0，第一行也按分数选，不按进来的顺序）；没有分数的行排在所有有分数的行之后，按进来的顺序。原来没有分数记作 −∞，λ = 0 时为了不算 0·(−∞) 把分数项一律写成 0，−∞ 也变成了 0，没有分数的行排到有分数的行前面。λ = 1 时只按分数，不算相似度：有限但范数超出 float 范围的向量，余弦是 NaN，0·NaN 仍是 NaN，原来让顺序不再看分数。0 < λ < 1 时这种向量的相似度同样是 NaN，没有为这种量级做缩放；但“没有分数的行排在后面”不靠 −∞ 比较保证：还有有分数的行时，没有分数的行不参加选择。NaN 比 −∞ 还“小”，原来第一个剩下的行没有分数也会被选中。固定的 λ 编译时检查；参数形式的 λ 要求 `param_schema` 声明的 min、max 在 [0, 1] 内（`TryParam` 的 `within`，通用于需要取值范围的算子）：参数值按声明校验、实验不能放宽，所以运行时读到的值一定在范围内，不用每个请求再查，也不用选“截断”还是“失败”。超出时惩罚变成奖励（λ = 2 原来照样通过）。选择逻辑抽成 `Order`，测试拿一份直接按公式写的参考实现在随机小窗口上逐个对照，比再加完整示例更能守住算法语义。
- **`TopK@1` 按精确的排序键比较**。原来分数都转成 double 比较，超过 2^53 的不同 int64（例如按 `entity_id` 排序时的大 id）会相等，再按 id 升序平分，于是升序和降序给出同样的顺序。现在 int64、int32 用翻转符号位后的无符号 64 位键，float64、float32 用 IEEE 754 全序键（−0.0 当作 +0.0），降序取反；缺失和 NaN 仍排在最后，平分仍按 `entity_id` 升序，不按行分配。排序键只在 `RowRanking.TryGetSortKey` 一处。`MmrDiversifier` 例外：它对分数做浮点运算（相关性减去相似度惩罚），仍按 float64 读取，超过 2^53 的 int64 分数会丢精度。
